# calendar-busy-sync

個人の Google カレンダーの予定を、別カレンダーに「予定あり」として同期する Google Apps Script。
予定のタイトルや内容は渡さず、時間枠だけを共有する。

## 概要

- 同期元: 実行アカウントの既定カレンダー (`primary`)
- 同期先: スクリプトプロパティ `SYNC_CALENDAR_ID` で指定したカレンダー
- 同期先に作る予定はすべてタイトル「予定あり」、公開設定は「限定公開」
- 作成した予定には `GUEST_EMAIL` を招待するので、招待先のアカウントにも予定が入る
- Calendar API (高度なサービス) を使い、期間内の予定を一括取得して差分だけ反映する

## セットアップ

1. GAS エディタ「プロジェクトの設定 > スクリプト プロパティ」に以下を追加
   | キー | 値 |
   | --- | --- |
   | `GUEST_EMAIL` | 招待先メールアドレス |
   | `SYNC_CALENDAR_ID` | 同期先カレンダー ID (`xxx@group.calendar.google.com`) |
2. `appsscript.json` で Calendar の高度なサービスが有効になっている (clasp push で反映される)
3. `syncBusyToCompany` を一度手動実行して権限を承認する
4. `syncBusyToCompany` を時間主導型トリガーで定期実行する

## 同期の挙動

### 対象期間

- 実行日の 0 時 (スクリプトのタイムゾーン) から `SYNC_DAYS` 日後 (既定 180 日) まで
- この期間外の予定は見ないし、期間外の同期済み予定も触らない
- そのため過去の同期済み予定は残り続ける。消したい場合は手で削除する

### 同期する予定・しない予定

同期元の予定のうち、次のものは同期しない。

| 条件 | 扱い |
| --- | --- |
| キャンセル済み (`status: cancelled`) | 同期しない |
| 自分が辞退した招待 | 同期しない |
| 勤務場所 (`eventType: workingLocation`) | 同期しない |
| 時間指定の予定で空き状況が「予定なし」(transparent) | 同期しない |
| 終日予定で空き状況が「予定なし」 | **同期する** (後述) |

それ以外はすべて「予定あり」として同期する。限定公開の予定も、予定名に関係なく同期する。

### 時間指定の予定

- 元予定と同じ開始・終了時刻で「予定あり」を 1 つ作る
- 元予定の時刻が変わると、同期先の時刻も追従する (作り直しではなく更新)
- 元予定が消えると、同期先の「予定あり」も消える

### 終日予定

- 1 日ごとに `ALLDAY_BUSY_START_HOUR`〜`ALLDAY_BUSY_END_HOUR` (既定 9:00〜18:00) の時間指定「予定あり」を作る
- 複数日の終日予定は各日に 1 枠ずつ作る。例: 11/3〜11/5 なら 11/3、11/4、11/5 に 9:00〜18:00 が 1 つずつ
- 元の終日予定が短くなると、不要になった日の枠だけ消える
- 終日予定は Google カレンダーの既定で空き状況が「予定なし」になるため、空き状況に関係なく同期する
- 同期先には終日予定としては作らない。あくまで時間指定の枠になる

### 繰り返し予定

- 繰り返し予定は各回に展開して、1 回ごとに独立した「予定あり」を作る
- ある回だけ時刻を変えたり削除したりした場合も、その回だけ追従する
- 内部的には「元予定の iCalUID + その回の開始時刻」で各回を識別している

### 同期先の予定の識別

- 同期先の予定の説明欄に `[BUSY_SYNC:<キー>]` を書き、拡張プロパティ `busySyncKey` にも同じキーを持たせる
- このキーで「どの元予定に対応する枠か」を判定する
- キーの形式
  - 単発の時間指定: `<iCalUID>:timed`
  - 繰り返しの時間指定: `<iCalUID>@<開始時刻ms>:timed`
  - 終日 (1 日ごと): `<iCalUID>[@<開始時刻ms>]:allday:<yyyy-MM-dd>`
- キーが付いていない予定 (同期先カレンダーに手で入れた予定など) は一切触らない

### 重複・不整合の自動修復

- 同じキーの「予定あり」が複数あれば、1 つだけ残して他を削除する
- 対応する元予定が無くなったキーの「予定あり」は削除する
- 時間指定であるべき枠が終日になっているなど形が違う場合は、削除して作り直す
- 同時実行 (トリガーと手動実行の重なりなど) は `LockService` で排他し、後から来た方はスキップする

### 通知

- 「予定あり」の作成・更新・削除のたびに、招待先 (`GUEST_EMAIL`) へ Google カレンダーの通知メールが送られる (`sendUpdates: 'all'`)
- 通知を止めたい場合は `コード.js` 内の `sendUpdates` を `'none'` にする

### エラー時

- 1 件の予定の処理に失敗しても全体は止めず、その予定だけスキップして次へ進む
- 実行ログに `source=… synced=… created=… updated=… duplicates=… removed=… errors=… time=…s` を出力する
- `errors` が 0 でない場合は、GAS エディタの「実行数」からエラー内容を確認する

### 既知の制約

- 同期先からの逆方向 (同期先で枠を動かしても元予定は変わらない) は非対応。同期先で動かした枠は次の実行で元に戻される
- GAS の実行時間制限 (6 分) を超えると途中で止まる。`SYNC_DAYS` を減らすと軽くなる
- タイムゾーンはスクリプトの設定 (`appsscript.json` の `timeZone`) に従う

## 開発

```sh
npm install -g @google/clasp
clasp login
clasp clone <スクリプトID>   # .clasp.json が生成される (git 管理外)
clasp push                  # ローカル → GAS
clasp pull                  # GAS → ローカル
```

`.clasp.json` と `config.local.js` は git 管理外。メールアドレスやカレンダー ID はコードに書かず、スクリプトプロパティに置く。
